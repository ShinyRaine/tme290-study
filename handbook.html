缩写与术语总表（中英对照，记不住名词就翻这里）

每一条 = 缩写｜英文全称（这才是记忆的锚）｜中文｜一句话它到底是什么。缩写记不住，是因为只记了三个字母、没记“它是哪几个词的头字母”。把全称读几遍，缩写自然就有意义了。

计算硬件

PLD ｜ Programmable Logic Device ｜ 可编程逻辑器件
一片能被重新配置成任意专用电路的芯片（它是硬件电路，常被误当成小电脑）。极快、省电。
FPGA ｜ Field-Programmable Gate Array ｜ 现场可编程门阵列
PLD 的一种，“门阵列”= 一大片逻辑门任你连线。和 PLD 当同义词记即可。
CPU ｜ Central Processing Unit ｜ 中央处理器
跑操作系统的通用大脑，能同时管很多程序，但实时性差。
GPU ｜ Graphics Processing Unit ｜ 图形处理器
专攻大规模并行矩阵运算，擅长视觉和神经网络。
MCU ｜ Microcontroller Unit ｜ 微控制器
一整台“电脑”缩到一块小芯片上（CPU+内存+输入输出全集成），专门控制一个设备。上电就在裸硬件上直接跑固定程序（即“无操作系统”），行为可预测 → 能实时。
OS ｜ Operating System ｜ 操作系统
管理硬件、调度多个程序的系统软件（如 Linux）；会为公平不停打断/切换各程序，好处是多任务、坏处是“何时轮到你”不确定 → 难实时。
real-time ｜ 实时
保证在规定时间内一定完成（准时、可预测）就叫实时。无 OS 的微控制器能实时；有 OS 的 CPU 难保证。（记准：实时=准时，跟快慢无关。）
ROM / RAM ｜ Read-Only / Random-Access Memory ｜ 只读存储器 / 随机存取存储器
ROM 存固定程序（断电不丢），RAM 是运行时的临时内存（断电即丢）。

传感器与相机

IR ｜ Infrared ｜ 红外
红外测距传感器，量程短、有大于零的最小量程。
RGB ｜ Red-Green-Blue ｜ 红绿蓝
三原色，彩色图像的通道。
ISP ｜ Image Signal Processor ｜ 图像信号处理器
相机里把原始感光数据加工成图片的芯片（白平衡/gamma/降噪）。
HSV ｜ Hue-Saturation-Value ｜ 色相-饱和度-明度
一种把“颜色”和“亮度”分开的颜色表示法，比 RGB 抗光照变化。

软件工程（第二薄弱块，重点读）

Docker ｜ 容器化工具
把程序连同它需要的所有依赖打包成一个“集装箱”，搬到任何机器上都一模一样地跑，根治“在我电脑上能跑、到别处就崩”。
镜像 vs 容器 ｜ image vs container
镜像 (image) 是打包好的静态模板（像安装光盘）；容器 (container) 是镜像跑起来的运行实例（像装好正在用的系统）。docker run = 从镜像创建并启动一个容器；docker build 才是造镜像。
Alpine / Ubuntu ｜ 两种 Linux 发行版
常用作 Docker 的基础镜像 (base image)：Ubuntu 大而全（功能多、体积大），Alpine 极简（体积小）；机器人求小 → 用 Alpine。
多阶段构建 ｜ multi-stage build
一个 Dockerfile 里写两个 FROM——第一阶段(builder)装编译工具把程序编出来，第二阶段只把编好的程序复制过去。好处：最终镜像只含编好的程序 → 很小（编译工具留在了 builder 阶段）。（24/25 的 Dockerfile 图题考的就是它。）
微服务 ｜ microservice
把一个大程序拆成许多各管一件事的独立小程序，各自单独开发/部署/替换，之间用统一协议发消息通信。（对立面 = 单体 monolithic：全焊成一大块。）
技术债 ｜ technical debt
为图快走捷径而欠下的“债”——当下省事，日后要花更多力气偿还（重构、修 bug）。
CI ｜ Continuous Integration ｜ 持续集成
管“编译+测试”阶段——每次提交代码，服务器自动构建并跑测试，确保新旧代码合得上。产出一个“通过测试的二进制”。
CD ｜ Continuous Deployment ｜ 持续部署
管“上线”阶段——把 CI 产出的、测试通过的二进制自动部署到产品（机器人）上。
CI/CD 的区别一句话
CI 在前，负责“造出并验好一个二进制”；CD 在后，负责“把它自动送上机器人”。合起来 = 从提交代码到部署上线全自动的流水线。
CE ｜ Continuous Experimentation ｜ 持续实验
上线后只先发给一部分机器人（灰度/金丝雀），用数据评估好坏再全量。
OTA ｜ Over-The-Air (update) ｜ 空中（无线）升级
远程把新软件“下发/装”到野外机器人上，方向是软件往下走。（对照：软件下发=OTA；数据回传=远程监控。）
HIL ｜ Hardware-In-the-Loop ｜ 硬件在环
把真实硬件接进测试回路一起测，可自动化。
SIL ｜ Software-In-the-Loop ｜ 软件在环
全程在软件仿真里跑真实代码（硬件用仿真替代）。
DIL / 数据回放 ｜ Data-In-the-Loop / data replay
回放事先录好的真实数据来测试，开环、完全可复现。
记忆串：SIL（纯软件）→ HIL（接真硬件）→ 数据回放（喂录好的数据）——都是“测试/验证”的手段，越往后越接近现实。
KPI ｜ Key Performance Indicator ｜ 关键性能指标
衡量机器人在野外表现好坏的量化指标。
SSH ｜ Secure Shell ｜ 安全外壳协议
远程登录到机器人上敲命令的工具（本职就是登录操作）。
UDP ｜ User Datagram Protocol ｜ 用户数据报协议
一种“发出去不等回执”的快速网络传输方式；libcluon 用它的组播 (multicast) 在微服务间传消息。
ROS ｜ Robot Operating System ｜ 机器人操作系统
一个大而全但单体式 (monolithic) 的机器人软件框架，作为 OpenDLV 的对照物出现。
OpenDLV
本课程用的、由许多 libcluon 微服务松散组成的机器人软件环境（相对 ROS 更轻更模块化）。
ARM64 / AMD64
两种CPU 指令集架构，详见《判断方法》一节的记忆钩子。

运动学与状态估计

ICR ｜ Instantaneous Centre of Rotation ｜ 瞬时旋转中心
某一瞬间整台车绕之转圈的那个点，是运动学推导的出发点。
KF ｜ Kalman Filter ｜ 卡尔曼滤波
用“模型预测”和“传感器测量”加权融合来估计状态的算法。只适用于线性系统。
EKF ｜ Extended Kalman Filter ｜ 扩展卡尔曼滤波
KF 的非线性版，用雅可比矩阵局部线性化；差速驱动（含 cos/sin φ）必须用它。
SLAM ｜ Simultaneous Localisation And Mapping ｜ 同时定位与建图
机器人边走边估自己位置、边建地图。
GNSS ｜ Global Navigation Satellite System ｜ 全球导航卫星系统
卫星定位的统称（GPS 是其中一种）；提供全局参照，但噪声大、频率低。
IMU ｜ Inertial Measurement Unit ｜ 惯性测量单元
测加速度和角速度的传感器，用于航位推算。

控制与决策

PID ｜ Proportional-Integral-Derivative ｜ 比例-积分-微分（控制器）
三项相加的经典控制器。P 主纠偏、I 消稳态误差、D 抑制振荡。
FSM ｜ Finite-State Machine ｜ 有限状态机
由“在某状态、满足条件就跳到另一状态”构成的行为切换逻辑；可用作用于全局变量的 if 语句实现。
BBR ｜ Behaviour-Based Robotics ｜ 基于行为的机器人学
让一堆简单行为并行、整体智能涌现的范式；灵感来自动物行为学 (ethology)。
ER ｜ Evolutionary Robotics ｜ 进化机器人学
用进化算法把控制器“演化”出来的范式，行为自然长成（无预设阶段）。
Symbolic AI ｜ 符号 AI
先建模再规划、分阶段、集中式的传统范式。
ANN ｜ Artificial Neural Network ｜ 人工神经网络
足够大的全连接网是“万能逼近器”，能拟合任意映射。
GA ｜ Genetic Algorithm ｜ 遗传算法
随机种群 → 按适应度选择 → 交叉+变异 → 下一代，进化机器人常用它。
A* / Dijkstra / RRT (Rapidly-exploring Random Tree 快速探索随机树)
路径规划算法；A* = Dijkstra + 启发式。

判断方法：遇到“拿不准”的题怎么下笔

三种常见的犹豫，各有破法：

1. 先分清问“好不好”还是“能不能”。看到 good idea / best / recommended / should / most efficient → 按最佳实践判：是坏做法就 FALSE（哪怕技术上做得到）。例 Q31“把视觉参数硬编码成常量 is a good idea”→ 坏做法 → FALSE。

⚠️ can 不等于自动 TRUE：若“能做到”只能靠歪招/坏做法才成立，答案还是 FALSE。例 Q13“用 git 追踪二进制”——你确实能把二进制 commit 进 git，但那是歪用（git 本职管源码、二进制溯源靠 CI/CD）→ FALSE；换成“追踪源码”才 TRUE。

2. 抓住考的是哪个对比。docker run 的职责就是“创建并启动一个容器”，所以 “docker run creates a Docker container” = TRUE。这题真正考容器 vs 镜像：24/25 陷阱版写 “docker run spawns a Docker image”（创建镜像）= FALSE（造镜像的是 docker build）。

⚠️ 关于“同名会报错”：默认不带 --name 时 Docker 每次都自动随机命名、照样新建容器；手动指定一个已存在的名字才会因重名报错——而那恰恰说明它“正要创建容器”。判这题只认准一件事：run 产出的是容器。

3. 给“设备↔CPU”配意义钩子。小设备省电用 ARM64（树莓派/机器人）、大服务器强力用 AMD64/x86（GitLab CI），架构不同 → 需交叉编译。Q29“架构不同是部署普遍难点”→ FALSE：交叉编译是常规操作、能轻松跨过这个差异。

兜底：答错不扣分，有一点把握就标 TRUE、绝不留空——6月有 12 分丢在“该选却留空”。

第 1 节 · 机器人的四种计算平台（★6月4题全错，L2）

原理：机器人硬件排成一条“越硬 ↔ 越软”的光谱。越靠硬件、结构越死板 → 跑得越快、越省电、越能保证“准时”(实时)，但能做的越少、越难改；越靠软件、越灵活 → 能做的越多、越好改，但越难保证准时。从硬到软：PLD/FPGA → 微控制器 → CPU → GPU。

这四个到底是什么：

· PLD/FPGA 可编程逻辑器件：“programmable” 指的是“内部硬件电路可被重新配置”（常被误读成“能跑程序”，本质是一片可重配的硬件电路）。它像一条焊死的并行流水线，信号一进去就直接算出结果，所以极快、极省电。

· 微控制器 (microcontroller)：一整台“电脑”缩在一块小芯片上——CPU、内存、输入/输出引脚全集成在一片里，专门控制一个设备（电机、传感器）。它上电就从只读存储器里、直接在裸硬件上跑一段固定程序（这就是所谓“无操作系统”）。正因执行时机完全可预测，这叫实时 (real-time)：保证在规定时间内一定完成（准时、可预测）。

· CPU 中央处理器：通用大脑，靠操作系统 (OS) 调度、同时跑很多个程序；代价是执行时机由 OS 决定（时机不定），所以实时性差。

· GPU 图形处理器：为大规模并行的矩阵运算优化，因此擅长计算机视觉和神经网络。

真题演练（英文原题 → 官方答案｜讲解；⚠️ = 6月做错）

  • 26 Q4 "A programmable logic device is extremely fast in execution." T ⚠️可重配电路、信号直穿 → 极快。
  • 26 Q5 "A microcontroller runs a very lean operating system (OS)." F ⚠️微控制器直接在裸硬件上跑程序（这正是它能实时的原因）。
  • 26 Q6 "A microcontroller is capable of real-time execution." T ⚠️裸机运行、执行时机可预测 → 实时。
  • 26 Q7 "A CPU is optimized to run one executable at a time." F ⚠️CPU 配 OS 就是为同时跑多个程序。

第 2 节 · 传感器与相机（L5）

原理：红外和超声波这类主动测距传感器（自己发出信号——红外光或声波——再接收回波来算距离）都有“看不清的近处”(大于零的最小量程) 和“够不着的远处”，其中超声波 (ultrasonic) 量程比红外 (IR) 远。彩色相机用拜耳阵列 (Bayer pattern)，每 2×2 格里 2 绿 1 红 1 蓝——因为人眼对绿最敏感，所以绿最多。卷帘快门 (rolling shutter) 逐行读出、更快更便宜（代价是运动变形）；全局快门 (global shutter) 整幅同一瞬间曝光、更贵更慢。内参 (intrinsic) 标定相机自身(焦距/畸变)；外参 (extrinsic) 才把相机和车体/其他传感器联系起来。

真题演练

  • 26 Q8 "IR sensors have a minimum range larger than zero." T主动测距都有 >0 的最小量程。
  • 26 Q9 "IR sensors have a longer range compared to ultrasonic sensors." F超声波更远。
  • 26 Q10 "A conventional RGB camera captures more light within the red wavelengths compared to blue and green." F拜耳阵列绿最多（2绿1红1蓝）。
  • 26 Q11 "A rolling shutter is faster compared to a global shutter." T ⚠️卷帘逐行读出更快（全局快门更慢更贵）。
  • 26 Q12 "Intrinsic calibration of a camera relates it to other sensors on the robot." F联系其他传感器的是外参；内参只标定相机自身(焦距/畸变)。

第 3 节 · 软件工程：Docker/微服务/CI-CD/OTA/git/部署（★分值最大、6月错7题，L2/L3）

原理（一行代码到机器人的完整链）：用 git 管源代码版本（可溯源）→ CI(持续集成) 每次提交自动构建并跑测试、产出验好的二进制 →（可带 HIL 真硬件测试）→ 交叉编译 (cross-compilation) 在 amd64 服务器上编出 arm64 机器人能跑的程序 → 打成 Docker 容器（docker run 从镜像创建容器；机器人用体积小的 Alpine）→ 拆成各管一件事的微服务（共享统一协议，利于 OTA/CI-CD）→ OTA(空中升级) 把软件下发到机器人；数据回传 = 远程监控。

⚠️ 两个反直觉但官方认定的点：微服务管的是部署/隔离/更新，算法选型是另一回事（所以“微服务让规划算法更容易”三年都是 F）；CPU 架构不同(ARM↔AMD64) 由交叉编译常规解决（所以“架构不同是普遍难点”为 F）。

真题演练 · Dockerfile（多阶段构建）

  • 24 Q3 / 25 Q3 "The build tools installed ... are needed in the resulting Docker image." Fbuild 工具只留在 builder 阶段；最终镜像只含编好的程序。
  • 24 Q4 / 25 Q4 "Every time a new Docker image is created ... the source code seems to be tested using pre-defined test cases." T构建时跑测试。
  • 24 Q2 / 25 Q2 "The word builder ... is user-specified." / "The second FROM ... will start over, creating a second Docker image." Tbuilder 是自定义名；第二个 FROM 开启全新镜像。
  • 24 Q5 / 25 Q5 "Ubuntu lacks the package libstdc++, making it unable to run the compiled program." F编造的依赖说法。
  • 24 Q6 / 25 Q6 "Line 24 immediately runs the compiled program." FCMD 声明的是“容器启动时才执行的命令”（构建阶段只是记下来）。
  • 25 Q1 "RUN commands can be placed before the first FROM command." FRUN 必须在 FROM 之后。
  • 24 Q1 "Line 2 indicate what base image the resulting image will be based on." F多阶段里最终镜像基于第二个 FROM。

真题演练 · 交叉编译 / git / CI / OTA / SSH

  • 24 Q14 "Cross-compilation is useful since we can compile software in Alpine to work with Ubuntu." F交叉编译 = 跨 CPU 架构(amd64↔arm64)；此句说成“跨发行版(Alpine→Ubuntu)”故 F。
  • 25 Q14 "... compile software on one CPU type (e.g. amd64) to run on another (e.g. arm64)." T这才是定义。
  • 26 Q26 "Cross-compilation can be especially useful ... as an automated part of a CI/CD pipeline." T
  • 26 Q29 "A general difficulty ... Raspberry Pi uses ARM64 while a GitLab server runs AMD64." F架构确实不同，但交叉编译是常规操作、能轻松跨过，所以“难点”说法为 F。（✓答对了）
  • 26 Q13 "Using git one can achieve traceability of binaries for robots." F ⚠️git 管源码、不管二进制；二进制溯源靠 CI/CD（见《判断方法》can 陷阱）。

第 4 节 · 差速驱动运动学（★唯一要推导，L4）

先认符号：r = 轮子半径；R = 左右轮到车体中心的距离（半个轮距）；L = 瞬心(ICR)到车体中心的距离；V = 车体前进速度；vL/vR = 左/右轮线速度；φ̇（读“phi-dot”）= 偏航角速度 (yaw rate)，即车头朝向转动的快慢。

原理：两轮转速不同 → 整车绕瞬时旋转中心 (ICR) 转，同一角速度 φ̇。由 vL = φ̇(L−R)、vR = φ̇(L+R)：相加 → V = (vR+vL)/2（无 R！）；相减 → φ̇ = (vR−vL)/(2R)（分母 2R！）。反解：vR = V + φ̇R。位置 = 速度积分：x₁ = x₀ + ∫(vR+vL)/2·cosφ dt。考场遇公式题就在草稿纸推一遍核对系数。

真题演练

  • 24 Q15 / 25 Q15 "The forward speed is calculated as V = R(v_R+v_L)/2" F多了 R；正确 V=(v_R+v_L)/2。
  • 24 Q16 / 25 Q16 "The yaw rate is calculated as φ̇=(v_R−v_L)/R" F分母应是 2R。
  • 26 Q34 "It can be shown that v_R = V + φ̇R" T由 V、φ̇ 反解单轮速。
  • 26 Q35 "The yaw rate is calculated as φ̇=(v_R−v_L)/2R" T分母 2R，对。
  • 26 Q36 "x₁ = x₀ + ∫ (v_R+v_L)/2·cosφ dt" T ⚠️位置 = 速度 Vx 的积分。

第 5 节 · 卡尔曼滤波（★含之前判错的 Q47，L8）

原理：KF 用“运动模型的预测”和“传感器的测量”加权融合来估状态，所以传感器噪声大 / 更新频率低时特别有用；它是在线递归算法、边跑边算即可；顺序永远先 Predict 后 Update。两模型分清：process model = 描述运动，observation model = 描述传感器怎么看。Kalman gain = 模型/测量的信任权重。

先搞清两个词：状态向量 (state vector) = 用一组数描述机器人此刻的状态，如 [x, y, φ]（位置+朝向）。线性 = 变量间只有加减和成比例（“直”的关系）；非线性 = 出现 sin、cos、平方这类“弯”的关系（如 cosφ、sinφ）。

线性化（关键）：标准 KF 只对线性系统成立。差速驱动的运动学关系（轮速↔V、φ̇）是线性的 → 标准 KF 能用；但一旦状态里带朝向角 φ、要算位置（出现 cosφ、sinφ）就非线性 → 改用 EKF（扩展卡尔曼）；动力学模型同样要用 EKF。

真题演练

  • 24 Q23 / 25 Q23 "... when sensors are noisy." T
  • 24 Q26 / 25 Q26 "A Kalman filter can be used for localization of a robot." T
  • 24 Q22 "... when there is no good model of the robot motion." T/F 均判对考官声明两个答案都接受。
  • 25 Q22 / 26 Q43 "A Kalman filter can not be used in a robot, since it requires recorded data." FKF 在线递归、边跑边算即可（照样能上机器人）。
  • 24 Q24 / 25 Q24 / 26 Q45 "The process model and observation model are two ways of modelling the sensors." Fprocess model 建的是运动。
  • 24 Q25 / 25 Q25 / 26 Q46 "The Kalman gain is used to increase the frequency of sensors." Fgain 是信任权重。
  • 26 Q44 "A Kalman filter first runs the step Update and then the step Predict." F先 Predict 后 Update。
  • 26 Q47 "The standard Kalman filter works well with the kinematic model of the differentially steered robot." T运动学关系是线性的。（✓答对了）

  • 26 Q49 "... works well with the state vector [x, y, φ]." F含 φ 的位置更新非线性 → 需 EKF。

第 6 节 · 控制/转向/PID + 仿真 + 路径规划（L6）

原理：横向控制 = 转向、纵向控制 = 速度。两点模型 (two-point)：近点管稳定 + 远点管前方曲率，输出是转向速率 (rate)（三年原句）。瞄点模型 (aim point) 的可调参数比预瞄模型少。PID：P 主纠偏、D 抑振、I 消稳态误差（转向主力是 P 和 D）。rate limiter（限速率器）把控制输出的变化速度限住、平滑视觉感知的跳变。模块化仿真 (modular simulation) = 把仿真器本身也做成一个微服务、和真实软件收发一样的消息，所以能无缝插进系统 → 与微服务架构天然契合、让 SIL 更容易（对照“单体 monolithic 仿真”= 焊成一大块）。Dijkstra 求最短路；A* = Dijkstra + 启发式 (heuristic，到终点的距离估计) 所以更快；两者都用于路径规划（找路）。

第 7 节 · 决策：FSM / BBR / 符号AI / 进化机器人 / ANN（★6月错3题，L7）

原理：三范式——符号 AI (Symbolic AI) 集中式、先建模再规划、分清晰阶段（感知→建模→规划→执行）；BBR 去中心，一堆原子行为 (atomic behaviours，最小的“感知→动作”单元，如“避障”“趋光”) 各自并行跑，整体智能靠涌现 (emergence，简单部件相互作用后冒出没被单独编程的复杂整体行为)，灵感来自动物行为学 (ethology)；进化/具身机器人的行为靠进化自然长出（无预设阶段）。FSM 描述行为间转移、可用 if 语句实现；参数由人工设定。包容架构 (subsumption architecture) = 把行为分层、高层能抑制 (suppress) 低层的输出，可由一组 FSM 搭起来。Braitenberg 车 = 传感器直接接电机的纯连线映射（无内部状态），教训是“造易析难”：造出来容易、从行为反推结构难。足够大的全连接 ANN = 万能逼近器 (universal approximation)，能拟合任意输入→输出映射。

第 8 节 · 机器人简史（★6月错2题，含之前判错的 Q2，L1）

原理 · 四位先驱：乌龟 Tortoise（W. Grey Walter, 1948–49）第一批电子自主机器人，用模拟电路（微控制器要到 1971 年才出现）证明涌现 (emergence)、会趋光 (phototaxis，朝光源移动，电量低时自己找充电站)；斯坦福小车 Stanford Cart（1960–80）靠摄像头视觉导航；Shakey（SRI, 1966–72）第一台能对自身行动推理的通用移动机器人（符号 AI，产出 A*、Hough 变换）；Braitenberg 车（1984）传感器直连电机、简单结构生复杂行为。

原理 · 炒作 vs 落地：80s 个人陪伴机器人炒作、90s 个人工作机器人炒作、00s 人形机器人(ASIMO)、10s 自动驾驶、20s LLM——都是炒作 (hype)，真正留下的是解决实际问题的产品（割草机、Roomba）。

  • 26 Q2 "Shakey was a robot with clear physical similarities to the Kiwi D2 robot." T ⚠️两者都是带摄像头+测距传感器的轮式移动机器人，物理构成相似。（记：看“轮式+载摄像头”这个共性）
  • 26 Q3 "So called personal robots was a concept that really took off in the 90s." F ⚠️80/90 年代只是炒作、没真正普及。

附录 · 考前 30 分钟速览（按错题优先级）

  1. 软件工程链（错最多）：git 管源码、二进制溯源靠 CI-CD；CI 含自动测试；HIL 可进自动测试；交叉编译 = 跨 CPU(amd64→arm64)、常规操作能跨过架构差异；docker run 创建容器、用小 Alpine；微服务共享协议、利于 OTA-CICD，管的是部署/隔离（“规划算法”三年 F）；OTA = 下发软件（数据回传 = 监控）。
  2. 计算硬件：PLD 可重配电路最快｜微控制器裸机运行 → 实时｜CPU 跑 OS 多任务但实时差｜GPU 管矩阵/视觉。
  3. 运动学：V=(vR+vL)/2（无 R）、φ̇=(vR−vL)/2R（分母 2R）、位置 = 速度积分；vR=V+φ̇R。
  4. 卡尔曼：先 Predict 后 Update；process = 运动、observation = 传感器；gain = 信任权重不提频率；运动学模型线性 → 标准 KF 可用，含 φ 的位置 [x,y,φ]/动力学非线性 → 用 EKF。
  5. 决策：符号 AI 分阶段｜BBR 并行涌现、源自动物行为学、选择不简单、可由 FSM/subsumption 搭、Braitenberg 不易解释｜进化机器人无预定义阶段｜大 ANN = 万能逼近。
  6. 控制：两点模型近+远点、输出速率；D 抑振；rate limiter 平滑视觉；瞄点参数少（非两个）；模块化仿真契合微服务、让 SIL 更易。
  7. 传感器：超声波比 IR 远；Bayer 绿最多；卷帘快门更快；内参管相机自身、外参连其他传感器。
  8. 历史：乌龟 = 模拟电路证涌现；Shakey 会推理、与 Kiwi 同为轮式载相机机器人（相似 = T）；个人机器人 90s 只是炒作没普及。
