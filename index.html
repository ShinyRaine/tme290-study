第 1 节 · 机器人的四种计算平台（★6月4题全错，L2）

原理：机器人硬件排成一条“越硬 ↔ 越软”的光谱。越靠硬件、结构越死板 → 跑得越快、越省电、越能保证“准时”(实时)，但能做的越少、越难改；越靠软件、越灵活 → 能做的越多、越好改，但越难保证准时。从硬到软：PLD/FPGA → 微控制器 → CPU → GPU。

这四个到底是什么（按课件 L2 原文展开）：

· PLD/FPGA 可编程逻辑器件：功能是在烧录 (flashing) 过程中加进去的，而且烧录改变的是芯片内部的实际硬件电路——不是“装了个程序”，而是把电路本身重新接线（这是它常被误解的地方）。支持输入/输出和程序循环。优点：执行极快、功耗极低（信号直接穿过硬件电路算出结果）；缺点：能实现的功能种类和规模都很受限。

· 微控制器 (microcontroller)：功能同样靠烧录——但烧的是程序：写进只读存储器 (ROM)，设备一上电就自动开始执行，全程没有操作系统。芯片虽小，却支持相对高级的程序和硬件外设（例如 WiFi、磁盘存储）。优点：简单、低功耗、灵活的实时系统，硬件集成能力出众（直接操纵电机、传感器引脚）；缺点：程序功能和执行灵活性受限。
——什么叫实时 (real-time)：保证在规定时限内一定完成、执行时机可预测。微控制器能实时，正是因为没有 OS 来打断它。（记准：实时=准时可预测，跟“算得快不快”无关。）

· CPU 中央处理器：运行时由操作系统管理（就是一台“普通电脑”，比如 Linux 内核）；多个程序并行运行，内存 (RAM) 和磁盘存储之间持续交互，支持任意软件和工具链。优点：能跑高级软件、速度也不慢；缺点：无法保证实时（何时轮到你的程序由 OS 调度决定），因此和硬件直接打交道的能力受限。

· GPU 图形处理器：执行模型类似微控制器，但专为矩阵运算设计（本为图形而生——图像就是矩阵），有标准化接口（如 Vulkan）；必须配一个 CPU 负责内存管理和控制。优点：矩阵运算性能极高 → 计算机视觉 (CV) 和深度神经网络 (DNN)；缺点：CPU–GPU 接口让底层实现变复杂。

课程重点用的是 CPU 系统（你的电脑 + 树莓派）。

第 2 节 · 传感器与相机（L5）

测距传感器（课程实物就是 Kiwi 上这两颗，L4）：它们都是主动传感器——自己发出信号、接收反射回来的信号来算距离。
· 超声波 (ultrasonic)，课程用 Devantech SRF08：发出 40 kHz 声波脉冲、收回波，量程 3 cm – 6 m，内置微处理器、走 I²C 总线。
· 红外 (IR)，课程用 Sharp GP2Y0A41SK0F：发红外光、收反射光，量程只有 4 – 30 cm，输出是模拟电压，而且电压和距离是非线性关系（要换算才能得到距离读数）。
两个考点由此而来：① 两者都有大于零的最小量程（贴到 0 距离测不了——回波/反射的几何路径在极近处失效）；② 超声波（米级）远比红外（厘米级）量程长。

相机的成像链（L5）：图像传感器 (image sensor) 是任何相机的核心部件（全球只有少数厂商生产）；相机 = 传感器芯片与使用者之间的接口。传感器分单通道 (mono) 和 RGB 两类。彩色是这么来的：传感器像素本身只感光强、不分颜色，所以在每个像素前盖一块红/绿/蓝滤光片，排成拜耳阵列 (Bayer pattern)——每 2×2 格 2 绿 1 红 1 蓝（人眼对绿光最敏感，绿色通道承担亮度细节，所以绿给双份）。每像素位深 8/10/12 bit。传感器直接输出的“拜耳图”还不是照片，要经过 ISP（图像信号处理）加工：去马赛克（把拜耳单层还原成 RGB 三通道）、白平衡、gamma 校正（补偿人眼的非线性感知）、tone mapping、降噪。几乎所有视觉算法和 ML/AI 工具用的都是 ISP 之后的数据。

两种快门到底怎么工作（课件只点名对比，机制如下）：
· 卷帘快门 (rolling shutter)：像素一行一行依次开始曝光、依次读出——同一幅图里，每一行记录的是略微不同时刻的世界。好处：每个像素不需要额外电路，传感器便宜、读出快（帧率高）；代价：拍高速运动的物体时各行错位，图像歪斜、晃动（“果冻效应”）。
· 全局快门 (global shutter)：所有像素在同一瞬间开始、同一瞬间结束曝光，结果先存进每个像素旁边的存储单元、再统一读出。没有任何运动畸变；但每个像素要多一套存储电路 → 更贵，读出通常也更慢。
考点一句话：卷帘 = 快 + 便宜 + 会变形；全局 = 同一瞬间 + 贵 + 慢。

标定（L5 的精确定义，别再记模糊了）：
· 内参标定 (intrinsic)：把图像像素坐标 (i, j) 变换到相机坐标 (x, y)——校正镜头光学畸变和相机自身特性（真实成像不可能落在完美矩形上；校正后每相邻像素间的角度增量相等）。用棋盘格标定（方格间距全部相等、已知）。只管相机自己。
· 外参标定 (extrinsic)：把相机坐标 (x, y) 变换到车体局部坐标 (X, Y)——取决于相机装在车上的位置和姿态；有了它才能把不同传感器的检测结果互相关联。若假设地面是平的，可用投影变换把每个像素直接投到地面上的 (X, Y)。车辆坐标系惯例：原点 = 前轴中心，X 朝前、Y 朝左。
考点：“把相机和其他传感器联系起来”的是外参，不是内参。

HSV vs RGB（L5）：HSV（色相-饱和度-明度）把图像的亮度信息 (luma) 和色彩信息 (chroma) 分开——颜色与亮度无关。所以光照变亮变暗时，按颜色过滤（如“找蓝色的锥桶”）依然稳定；直接在 RGB 里筛颜色，三个通道全都随光照一起变，很难写出稳的阈值。（OpenCV 里 H 用 0–180 而非 0–360。）

第 3 节 · 软件工程：Docker/微服务/CI-CD/OTA/git/部署（★分值最大、6月错7题，L2/L3）

原理（一行代码到机器人的完整链）：用 git 管源代码版本（可溯源）→ CI(持续集成) 每次提交自动构建并跑测试、产出验好的二进制 →（可带 HIL 真硬件测试）→ 交叉编译 (cross-compilation) 在 amd64 服务器上编出 arm64 机器人能跑的程序 → 打成 Docker 容器（docker run 从镜像创建容器；机器人用体积小的 Alpine）→ 拆成各管一件事的微服务（共享统一协议，利于 OTA/CI-CD）→ OTA(空中升级) 把软件下发到机器人；数据回传 = 远程监控。

容器为什么好（L2）：容器是“操作系统级虚拟化”——共享宿主机内核、只隔离应用环境，所以比虚拟机（每台都背一整套 OS + 内核）轻得多。三大好处：把二进制放进定义良好的隔离环境；跨平台可搬运；每个软件功能打成一个独立包 → 天然适合 OTA。构建链同样受益：源码进隔离的构建环境、构建逻辑也可搬运、还能装交叉编译工具（如 amd64 → arm）。

上线之后的闭环（L2）：OTA 不只服务野外产品，也帮开发——把办公室拉近实物、给整个车队做版本管理；远程监控把野外数据传回后台，用 KPI（给整个机器人车队定义的量化指标）做正式评估，KPI 是 CE（持续实验）的使能器；CE 的典型做法：新版本先只发给一部分（如 20%）用户/机器人，数据证明更好再全量——Tesla 甚至在功能公开发布前先“静默”装上车、以 what-if 模式远程观察，每天约百万英里的数据。

调参数用哪个工具（L5，Q31–33 的原理）：三个选择各有硬伤——仿真：结果通常不可复现、永远不够真实（运动和传感器）、解动力学方程算得慢；实机：不可复现、每次测试时间开销大；data replay（数据回放）：开环 → 结果完全可复现，同一段录像反复喂给感知算法调阈值，效率最高（课件案例的时间分配：50% 回放 / 20% 仿真 / 30% 实机）。但注意：回放是开环的——你的控制输出不会改变录像内容，所以调不了运动控制参数（那需要闭环反馈，用仿真或实机）。

⚠️ 两个反直觉但官方认定的点：微服务管的是部署/隔离/更新，算法选型是另一回事（所以“微服务让规划算法更容易”三年都是 F）；CPU 架构不同(ARM↔AMD64) 由交叉编译常规解决（所以“架构不同是普遍难点”为 F）。

第 4 节 · 差速驱动运动学（★唯一要推导，L4）

先认符号：r = 轮子半径；R = 左右轮到车体中心的距离（半个轮距）；L = 瞬心(ICR)到车体中心的距离；V = 车体前进速度；vL/vR = 左/右轮线速度；φ̇（读“phi-dot”）= 偏航角速度 (yaw rate)，即车头朝向转动的快慢。

原理：两轮转速不同 → 整车绕瞬时旋转中心 (ICR) 转，同一角速度 φ̇。ICR 距车体中心距离 L，则 vL = φ̇(L−R)、vR = φ̇(L+R)：相加 → V = (vR+vL)/2（无 R！）；相减 → φ̇ = (vR−vL)/(2R)（分母 2R！）。反解：vR = V + φ̇R。

位姿 = 速度积分（L4 完整三件套）：把 V 分解成 Vx = V·cosφ、Vy = V·sinφ，再积分：
x₁ = x₀ + ∫ (vR+vL)/2 · cosφ dt　｜　y₁ = y₀ + ∫ (vR+vL)/2 · sinφ dt　｜　φ₁ = φ₀ + ∫ (vR−vL)/(2R) dt
x 配 cos、y 配 sin——出题人爱把它们对调来钓鱼。考场遇公式题就在草稿纸推一遍核对系数。

运动学 vs 动力学（这条区分第 5 节要用）：运动学只回答“给定轮速，车的位姿怎么变”，不管这个运动是怎么被力产生的；动力学才考虑作用在车上的力和扭矩（电机转矩 τ、质量 M、转动惯量 I）。仿真里用动力学模型 + Euler 法逐时间步积分（先由转矩更新 V 和 φ̇，再更新 φ，最后更新位置）。

第 5 节 · 卡尔曼滤波（★含之前判错的 Q47，L8）

原理（KF 讲义原文展开）：卡尔曼滤波把“把多个数据来源合并”这件事写成了数学公式，被称为最优估计器 (optimal estimator)。它每个时间步跑两步、顺序固定：① Predict——用 process model 从上一时刻的状态预测当前状态；② Update——用传感器读数（经 observation model）估计预测的偏差，把预测修正过来。它天生善于处理不同更新频率的数据（传感器没来新数据时靠模型顶上），也善于压噪声——所以“传感器频率太低/噪声太大时常用 KF”都是 T。

两个模型的精确定义（讲义原话）：process model 描述“状态如何从上一步转移到下一步”（可含控制输入；讲义特别点名：“这里的好例子就是差速驱动的运动学模型”）；observation model 描述“传感器读数与状态变量如何对应”（含标定信息：比例缩放、去偏置）。所以“两个模型都是在建模传感器”= F——process model 建的是运动。

Kalman gain：噪声本身不可预测，但可以在“上一步的估计”和“当前的观测”之间做信任权衡——gain 就是这个权重（讲义：“gain 装着系统对每个观测的信任度”）。它不能提高传感器频率（那是整个滤波器的效果，不是 gain 的职责）。

在线递归：滤波器可以在机器人运行时全程在线跑，也可以跑事先录好的数据——两者都行，所以“KF 需要录制数据、不能上机器人”= F。

线性化（关键考点）：标准 KF 假设 process 和 observation 模型都是线性的（变量间只有加减和成比例）。模型非线性时用 EKF：在当前状态点附近用雅可比矩阵 (Jacobian) 估计模型的局部导数（“模型对状态的小变化如何响应”），拿这个局部线性近似继续跑 KF 框架。对差速驱动：轮速 ↔ V、φ̇ 的运动学关系是线性的 → 标准 KF 可用；但状态向量取 [x, y, φ] 时，位置更新出现 cosφ、sinφ（“弯”的关系）→ 非线性 → 要 EKF；动力学模型（含力/扭矩）同样非线性 → EKF。

它俩的用武之地（L8）：传感器融合——GNSS 偶尔给一个全局参照（噪声大、频率低），轮编码器/IMU 在两次 GNSS 之间跟踪运动，内部（process）模型负责去噪，KF 把三者合并。SLAM——把 GNSS 也去掉，靠反复观测到的路标同时定位+建图（EKF-SLAM 的状态向量除 [x,y,φ] 外还装着每个路标的坐标，大小 3+2n 随发现的路标增多而变大；重看到一个路标出现在“它该在的位置”，不确定度就下降）。

第 6 节 · 控制/转向/PID + 仿真 + 路径规划（L6）

横向 vs 纵向（L6）：纵向控制 = 沿 X 轴（车头方向）的局部速度调节；横向控制 = 转向、保持在路上。导航拆成三个概念：定位（在地图里找到自己）→ 路径规划（找一条从当前位置到目标的高效路径，全局）→ 路径跟随（施加控制沿路走，局部）。

三个转向模型（都来自“人怎么开车”的研究，Kondo 1950s 起）：
· 瞄点模型 (aim point)：盯住前方一个目标点，控制律 δ = k·ε（ε 是望向该点的角度误差）——只有 1 个可调参数 k。
· 预瞄模型 (preview)：沿前方路径取一串预瞄点综合决定转向（最著名的模型用 8 个点）→ 参数自然更多。所以“瞄点参数比预瞄少”= T，“瞄点有两个可调参数”= F。
· 两点模型 (two-point, Salvucci & Gray 2004)：模仿人眼——远点是注视点（位置随情境变化），负责监测横向稳定性、预判前方道路曲率；近点在眼前的道路中心，用余光（不注视）监测当前横向位置。输出是转向速率 (rate)：只有当近点/远点在视野中动起来、或近点不在正前方时，才转动方向盘——课件的金句：“转向不是在移动车辆，而是在移动感知到的世界”。

PID 与 rate limiter：课件原话“大多数场合 PID 完全够用”。P 按当前误差纠偏（主力）、I 累积历史误差消除稳态偏差、D 按误差变化率提供阻尼 → 抑制振荡；转向靠 P 和 D，I 不是主角。rate limiter（限速率器）限制控制输出的变化速度：视觉感知是逐帧的、会跳变（检测忽有忽无、位置抖动），直接驱动转向会让车“抽搐”——限速率器把突变削平滑。

模块化仿真（L4 的原理，一句话就懂）：微服务不知道数据从哪来，只关心消息的类型和内容——所以任何一个微服务都可以被换成仿真件（虚拟相机、虚拟轮编码器、虚拟车体……与 data replay 是同一个原理），甚至一部分仿真、一部分实物混着跑。这就是它与微服务架构天然契合、SIL/HIL 都容易做的原因。对照单体仿真（Gazebo、AirSim 这类独立世界）：要整个另建一套，还容易掉进“仿真优化的兔子洞”（无止境地调仿真本身）。

路径规划（L6）：Dijkstra——从起点出发反复做两件事：把当前节点的所有未访问邻居“松弛”（发现更短路径就更新它的距离、记下前驱），然后在所有未访问节点里挑距离最小的作为下一个当前节点；保证最短路，但要摸遍大量节点 → 基础、慢。A* = Dijkstra + 启发式（对“到终点还有多远”的估计，优先探索有希望的方向）→ 常用、快。D* Lite 适合真实世界（环境变化时增量重规划）。它们都是找路的，不管速度控制。

第 7 节 · 决策：FSM / BBR / 符号AI / 进化机器人 / ANN（★6月错3题，L7）

三种范式：符号 AI (Symbolic AI)——集中式、功能分解、分清晰的数据处理阶段（感知→建模→规划→执行），先把世界建成模型再在模型上推理规划。BBR——去中心：一堆原子行为 (atomic behaviours，最小的“感知→动作”单元，如“避障”“趋光”) 各自并行跑（可同时激活），整体智能靠涌现 (emergence，简单部件相互作用后冒出没被单独编程的复杂整体行为)，灵感来自动物行为学 (ethology)；行为的选择与协调是核心难题——课件原话：“行为建模归根结底就是简单孤立组件的协调与调参”，所以“behaviour selection is trivial”= F。进化/具身机器人 (ER)——具身智能主张“智能只能相对于一个物理身体、在情境化的行为中讨论”；行为靠进化自然长出，没有预定义的行为或数据处理阶段。

FSM（L7 定义）：由离散逻辑状态组成的图；每个状态 = 一个具体的孤立行为（如漫游、左转）；特定条件（如刺激超过阈值）触发到另一状态的转移；FSM 本身不强加任何行为层级。可以实现为作用在全局变量上的一组 if 语句。参数（阈值等）由人工设定——“FSM 自动调参”= F。

包容架构 (subsumption architecture，L7 原文)：一种反应式行为架构——行为按层级排序；每个行为有自己的激活条件、非激活即休眠；各行为并行运行，但高层行为激活时会抑制 (suppress) 低层行为的输出；模块化：新行为可以直接叠在既有行为之上（增量扩展）；激活条件的调参决定整体表现。每个行为内部就可以是一个 FSM——课件例子：“逃离 (Escape)”行为 = 4 状态 FSM（等待碰撞→右转→倒车→左转，靠碰撞方向和超时触发转移）→ 所以“subsumption 可由一组 FSM 搭出来”= T。

Braitenberg 车（1984）：传感器直连电机的纯连线映射——“决策”被还原成一个传感器→执行器映射，映射本身就是行为（没有内部状态，所以“Braitenberg 是 FSM”= F）。在有多个刺激源的复杂环境里，它会表现出看似智能的复杂动态行为。教训是原书那句名言：“从行为的观察反推内部结构，比先造出产生该行为的结构要难得多”——造易析难，所以“简单原子行为导致容易解释的整体行为”= F。

进化怎么“长”出行为（L7 GA 流程）：随机生成初始种群 → 把每条染色体解码成一个行为模型 → 放进环境里实际跑、评估 → 打适应度 (fitness) 分 → 选优 + 交叉/变异产生下一代。优点：能处理不可微的目标函数、没有完整数学模型的优化问题（如仿真或 HIL 里评估），靠并行搜索对付多局部最优。

ANN（L7）：全连接网络是“更一般的输入→输出映射”、一块行为的白板结构——能同时容纳许多并行、混合的行为；调的是每个神经元的权重 + 偏置（y = φ(w·x+b)），激活函数（如 sigmoid）把输入输出压在 [0,1]。足够大的全连接 ANN 能拟合任意输入→输出映射（万能逼近）——考试为 T。

第 8 节 · 机器人简史（★6月错2题，含之前判错的 Q2，L1）

原理 · 四位先驱（L1 细节版）：
· 乌龟 Tortoise（W. Grey Walter, 1948–49）：第一批电子自主机器人。造它的目的就是证明“少量‘脑细胞’之间的丰富连接可以产生非常复杂的行为”——即涌现 (emergence)。会趋光 (phototaxis)：电量低时能自己找到充电站。全部用模拟电路实现——微控制器 1971 年才发明，晚了 23 年，所以“乌龟以首用微控制器闻名”= F。
· 斯坦福小车 Stanford Cart（1960–80，三阶段）：1960–63 为遥操作登月任务研究视频遥控；1964–71 在受控光照下沿高对比白线低速自动行驶；1971–80 用 TV 相机做视觉导航、在实验室缓慢绕障。
· Shakey（SRI 斯坦福研究院, Nils Nilsson 等, 1966–72）：第一台能对自身行动进行推理的通用移动机器人；还能做自然语言处理——把书面命令拆解成基本任务。对机器人学和 AI 影响巨大：A* 搜索算法、Hough 变换都出自这个项目。它和 Kiwi 一样是带相机+测距传感器的轮式移动机器人（26 Q2 说“物理构成相似”= T）。
· Braitenberg 车（1984，Valentino Braitenberg 的书）：传感器直连电机、简单结构生出复杂行为（详见第 7 节）。

原理 · 炒作 vs 落地（L1 年表）：80s 个人陪伴机器人炒作 → 90s 深度神经网络炒作 + 个人工作机器人炒作 → 00s 第一波人形机器人（ASIMO 惊艳大众；后来演化出更实用的 Boston Dynamics 机器狗）→ 10s 自动驾驶 + 机器学习炒作 → 20s LLM“AI”炒作 + 第二波人形炒作。真正商业落地的是解决实际问题的朴素产品：Husqvarna 的割草机器人、iRobot 的 Roomba 扫地机——所以“个人机器人在 90 年代真正起飞了”= F（只是炒作）。

计算硬件

PLD ｜ Programmable Logic Device ｜ 可编程逻辑器件
一片能被重新配置成任意专用电路的芯片（它是硬件电路，常被误当成小电脑）。极快、省电。
FPGA ｜ Field-Programmable Gate Array ｜ 现场可编程门阵列
PLD 的一种，“门阵列”= 一大片逻辑门任你连线。和 PLD 当同义词记即可。
CPU ｜ Central Processing Unit ｜ 中央处理器
跑操作系统的通用大脑，能同时管很多程序，但实时性差。
GPU ｜ Graphics Processing Unit ｜ 图形处理器
专攻大规模并行矩阵运算，擅长视觉和神经网络。
MCU ｜ Microcontroller Unit ｜ 微控制器
一整台“电脑”缩到一块小芯片上（CPU+内存+输入输出全集成），专门控制一个设备。上电就在裸硬件上直接跑固定程序（即“无操作系统”），行为可预测 → 能实时。
OS ｜ Operating System ｜ 操作系统
管理硬件、调度多个程序的系统软件（如 Linux）；会为公平不停打断/切换各程序，好处是多任务、坏处是“何时轮到你”不确定 → 难实时。
real-time ｜ 实时
保证在规定时间内一定完成（准时、可预测）就叫实时。无 OS 的微控制器能实时；有 OS 的 CPU 难保证。（记准：实时=准时，跟快慢无关。）
ROM / RAM ｜ Read-Only / Random-Access Memory ｜ 只读存储器 / 随机存取存储器
ROM 存固定程序（断电不丢），RAM 是运行时的临时内存（断电即丢）。

传感器与相机

IR ｜ Infrared ｜ 红外（测距传感器）
发红外光、收反射光来测距。课程实物 Sharp GP2Y0A41SK0F：量程仅 4–30 cm，输出模拟电压且与距离非线性。最小量程大于零。
Ultrasonic ｜ 超声波（测距传感器）
发 40 kHz 声波脉冲、收回波测距。课程实物 Devantech SRF08：量程 3 cm–6 m（远比红外长），内置微处理器、I²C 接口。
RGB ｜ Red-Green-Blue ｜ 红绿蓝
三原色，彩色图像的通道。传感器靠拜耳滤色阵列（2×2 = 2绿1红1蓝）产生颜色信息。
ISP ｜ Image Signal Processor ｜ 图像信号处理器
把传感器输出的原始拜耳图加工成正常照片：去马赛克（拜耳→RGB）、白平衡、gamma 校正、tone mapping、降噪。视觉算法几乎都用 ISP 之后的数据。
rolling / global shutter ｜ 卷帘快门 / 全局快门
卷帘：像素逐行曝光读出（每行时刻略不同）→ 便宜、快、拍运动会歪斜；全局：所有像素同一瞬间曝光再统一读出 → 无畸变、但更贵更慢。
HSV ｜ Hue-Saturation-Value ｜ 色相-饱和度-明度
把亮度 (luma) 和色彩 (chroma) 分开的颜色表示法——颜色与亮度无关，光照变化时按颜色过滤依然稳定，比 RGB 好用。

软件工程（第二薄弱块，重点读）

Docker ｜ 容器化工具
把程序连同它需要的所有依赖打包成一个“集装箱”，搬到任何机器上都一模一样地跑，根治“在我电脑上能跑、到别处就崩”。
镜像 vs 容器 ｜ image vs container
镜像 (image) 是打包好的静态模板（像安装光盘）；容器 (container) 是镜像跑起来的运行实例（像装好正在用的系统）。docker run = 从镜像创建并启动一个容器；docker build 才是造镜像。
Alpine / Ubuntu ｜ 两种 Linux 发行版
常用作 Docker 的基础镜像 (base image)：Ubuntu 大而全（功能多、体积大），Alpine 极简（体积小）；机器人求小 → 用 Alpine。
多阶段构建 ｜ multi-stage build
一个 Dockerfile 里写两个 FROM——第一阶段(builder)装编译工具把程序编出来，第二阶段只把编好的程序复制过去。好处：最终镜像只含编好的程序 → 很小（编译工具留在了 builder 阶段）。（24/25 的 Dockerfile 图题考的就是它。）
微服务 ｜ microservice
把一个大程序拆成许多各管一件事的独立小程序，各自单独开发/部署/替换，之间用统一协议发消息通信。（对立面 = 单体 monolithic：全焊成一大块。）
技术债 ｜ technical debt
为图快走捷径而欠下的“债”——当下省事，日后要花更多力气偿还（重构、修 bug）。
CI ｜ Continuous Integration ｜ 持续集成
管“编译+测试”阶段——每次提交代码，服务器自动构建并跑测试，确保新旧代码合得上。产出一个“通过测试的二进制”。
CD ｜ Continuous Deployment ｜ 持续部署
管“上线”阶段——把 CI 产出的、测试通过的二进制自动部署到产品（机器人）上。
CI/CD 的区别一句话
CI 在前，负责“造出并验好一个二进制”；CD 在后，负责“把它自动送上机器人”。合起来 = 从提交代码到部署上线全自动的流水线。
CE ｜ Continuous Experimentation ｜ 持续实验
上线后只先发给一部分机器人（灰度/金丝雀），用数据评估好坏再全量。
OTA ｜ Over-The-Air (update) ｜ 空中（无线）升级
远程把新软件“下发/装”到野外机器人上，方向是软件往下走。（对照：软件下发=OTA；数据回传=远程监控。）
HIL ｜ Hardware-In-the-Loop ｜ 硬件在环
把真实硬件接进测试回路一起测，可自动化。
SIL ｜ Software-In-the-Loop ｜ 软件在环
全程在软件仿真里跑真实代码（硬件用仿真替代）。
DIL / 数据回放 ｜ Data-In-the-Loop / data replay
回放事先录好的真实数据来测试，开环、完全可复现。
记忆串：SIL（纯软件）→ HIL（接真硬件）→ 数据回放（喂录好的数据）——都是“测试/验证”的手段，越往后越接近现实。
KPI ｜ Key Performance Indicator ｜ 关键性能指标
衡量机器人在野外表现好坏的量化指标。
SSH ｜ Secure Shell ｜ 安全外壳协议
远程登录到机器人上敲命令的工具（本职就是登录操作）。
UDP ｜ User Datagram Protocol ｜ 用户数据报协议
一种“发出去不等回执”的快速网络传输方式；libcluon 用它的组播 (multicast) 在微服务间传消息。
ROS ｜ Robot Operating System ｜ 机器人操作系统
一个大而全但单体式 (monolithic) 的机器人软件框架，作为 OpenDLV 的对照物出现。
OpenDLV
本课程用的、由许多 libcluon 微服务松散组成的机器人软件环境（相对 ROS 更轻更模块化）。
ARM64 / AMD64
两种CPU 指令集架构。记忆钩子：小设备省电用 ARM64（树莓派/机器人）、大服务器强力用 AMD64/x86（GitLab CI），架构不同 → 需交叉编译（常规操作，不算"难点"）。

运动学与状态估计

ICR ｜ Instantaneous Centre of Rotation ｜ 瞬时旋转中心
某一瞬间整台车绕之转圈的那个点，是运动学推导的出发点。
KF ｜ Kalman Filter ｜ 卡尔曼滤波
把“合并多个数据来源”写成数学公式的最优估计器：每步先用模型预测、再用测量修正。只适用于线性模型（非线性用 EKF）。
EKF ｜ Extended Kalman Filter ｜ 扩展卡尔曼滤波
KF 的非线性版，用雅可比矩阵局部线性化；差速驱动（含 cos/sin φ）必须用它。
SLAM ｜ Simultaneous Localisation And Mapping ｜ 同时定位与建图
机器人边走边估自己位置、边建地图。
GNSS ｜ Global Navigation Satellite System ｜ 全球导航卫星系统
卫星定位的统称（GPS 是其中一种）；提供全局参照，但噪声大、频率低。
IMU ｜ Inertial Measurement Unit ｜ 惯性测量单元
测加速度和角速度的传感器，用于航位推算。

控制与决策

PID ｜ Proportional-Integral-Derivative ｜ 比例-积分-微分（控制器）
三项相加的经典控制器。P 主纠偏、I 消稳态误差、D 抑制振荡。
FSM ｜ Finite-State Machine ｜ 有限状态机
由“在某状态、满足条件就跳到另一状态”构成的行为切换逻辑；可用作用于全局变量的 if 语句实现。
BBR ｜ Behaviour-Based Robotics ｜ 基于行为的机器人学
让一堆简单行为并行、整体智能涌现的范式；灵感来自动物行为学 (ethology)。
ER ｜ Evolutionary Robotics ｜ 进化机器人学
用进化算法把控制器“演化”出来的范式，行为自然长成（无预设阶段）。
Symbolic AI ｜ 符号 AI
先建模再规划、分阶段、集中式的传统范式。
ANN ｜ Artificial Neural Network ｜ 人工神经网络
足够大的全连接网是“万能逼近器”，能拟合任意映射。
GA ｜ Genetic Algorithm ｜ 遗传算法
随机种群 → 按适应度选择 → 交叉+变异 → 下一代，进化机器人常用它。
A* / Dijkstra / RRT (Rapidly-exploring Random Tree 快速探索随机树)
路径规划算法；A* = Dijkstra + 启发式。
